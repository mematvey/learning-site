## Задачи (условия; ответы при исходных параметрах проверены оркестратором)
1. 18 абитуриентов случайно распределяются на два факультета по 9. Среди них 5 медалистов. P: А) все медалисты на одном факультете = **1/34**; В) на одном 2, на другом 3 = **12/17**.
2. Два офиса, одинаковые принтеры; P(тонер кончится у одного) = 0.3; P(у обоих) = 0.12. P(к концу дня тонер останется в обоих) = **0.52 = 13/25**.
3. Студент знает 20 вопросов из 25, задают два. P(знает оба) = **19/30**.
4. В вазе 10 мандаринов, 5 апельсинов, 2 лимона; вынимают три по одному. а) последовательно лимон, апельсин, мандарин = **5/204**; б) три разных фрукта = **5/34**.
5. Партия 25 деталей, 20 стандартных; проверяют три. а) все стандартные = **57/115**; б) только вторая бракованная = **19/138**; в) ровно одна бракованная = **19/46**.
6. Два кубика: P(чётная сумма | хотя бы на одном 6) = **5/11**.
7. Карточки 1–6, ребёнок составляет число: а) трёхзначное, P(123) = **1/120**; б) шестизначное, P(123456) = **1/720**.
8. Карточки 1,1,1,2,2,3; P(случайная выкладка = 111223) = **1/60**.
9. *(Условие восстановлено: на скриншоте обрезано — так и пометить в тексте.)* В отделе 30 сотрудников, 10 из них — менеджеры. Случайно выбирают комиссию из 5 человек. а) ровно 2 менеджера = C(10,2)C(20,3)/C(30,5) **≈ 0.3600**; б) хотя бы один менеджер = 1 − C(20,5)/C(30,5) **≈ 0.8912**.

## ST1. Математика — `feat(prob): exact combinatorics, simulation and problem definitions`
Владеешь: `src/lib/prob/**` кроме `types.ts`.
- `rational.ts`: `rat(num, den)`, `add/sub/mul/div`, `toNumber`, `formatRational` («a/b» или целое), `fromDecimal(x, places=6)`; всё на BigInt, сокращение по НОД.
- `comb.ts`: `factorial`, `nCr`, `nPr`, `multinomial(counts)` — BigInt; `nCr` = 0n при k<0 или k>n; `logFactorial` для больших n.
- `hypergeom.ts`: `hypergeomPmf(N, K, n, k): Rational`, `hypergeomAtLeast(N, K, n, k)`.
- `rng.ts`: seeded `mulberry32(seed)`, `shuffle`, `sampleWithoutReplacement(n, k, rng)`.
- `simulate.ts`: `runSimulation({ trials, trial, seed?, chunk = 2000, onProgress })` — выполняет частями (`setTimeout(0)` между чанками, UI не блокируется), возвращает `{ cancel(), done: Promise<SimulationState> }`; `series` — ~150 точек на лог-шкале по числу испытаний для каждого ключа.
- `problems/p1.ts` … `p9.ts` + `problems/index.ts` (`PROBLEMS: ProblemDef[]`): по контракту `ProblemDef`. Параметры (дефолты = условие): p1 `{total:18, medalists:5, k:2}` (два факультета по total/2; total чётное 2–40; medalists ≤ total; вопрос В — «на одном k, на другом medalists−k»); p2 `{pA:0.3, pB:0.3, pAB:0.12}` (валидация: pAB ≤ min(pA,pB), pAB ≥ pA+pB−1; точная дробь через `fromDecimal`); p3 `{N:25, K:20, n:2}`; p4 `{mandarins:10, oranges:5, lemons:2}`; p5 `{N:25, good:20, n:3}` (б требует n ≥ 2); p6 `{faces:6, target:6}`; p7 `{cards:6, len:3}`; p8 `{ones:3, twos:2, threes:1}`; p9 `{N:30, K:10, n:5, k:2}`. `steps`: пошаговый разбор с подставленными числами (TeX в `tex`), `altSteps` — другой способ (например, последовательное умножение вместо сочетаний), `condition` — текст условия с текущими числами.
- Тесты (`*.test.ts`): точные ответы при дефолтах = значения выше (дроби); для каждого вопроса Монте-Карло 40 000 испытаний (seed) в пределах 4σ от точного; валидация отклоняет невалидные/крайние (0, максимум) и функции не падают на граничных валидных; BigInt-точность на больших n (например, C(100,50)).

## ST2. Карточка задачи — `feat(problems): problem card with params, experiment, spoilers, progress`
Владеешь: `src/lib/components/problems/**`.
Компоненты (используй типы из `types.ts`; математику — из `$lib/prob/...` по описанию ST1: `formatRational`, `toNumber`, `runSimulation`):
- `ProblemCard.svelte` — пропсы `{ problem: ProblemDef; viz?: Snippet<[ProblemParams]> }`. Состав: заголовок «Задача N» (`id` → якорь `#pN`), условие (`problem.condition(params)`), `ParamPanel` (ползунки/поля по `params`, ошибки `validate` текстом, при ошибке ответы и эксперимент неактивны), `AnswerView` (по каждому вопросу: точная дробь и десятичное, мгновенно), слот `viz(params)`, `Experiment`, `Spoilers`, кнопка «Решил ✓».
- `Experiment.svelte` — поле N (по умолчанию 10 000, 100–1 000 000), «Запустить»/«Остановить», прогресс; график сходимости эмпирической доли к теоретической (свой SVG по ширине контейнера, горизонтальная линия точного значения, лог-ось X, 12–13px текст), по линии на вопрос, цвета `--cat-*`.
- `Spoilers.svelte` — три `<details>` (закрыты): «Подсказка» → «Разбор» (`steps`, KaTeX через `katex.render`, `throwOnError: false`) → «Ответ»; разбор и ответ пересчитываются при смене параметров; открытие «Разбора»/«Ответа» отмечает `revealed`.
- Глубина (контекст уровней `$lib/levels`, `useLevels()`/`LEVELS_CONTEXT`): d=1 — ответ и формула (первый шаг с `tex`), без разбора; d≥2 — полный разбор; d=3 — плюс «Другой способ» (`altSteps`). Блоки карточки помечай `data-block` и `id` (`pN-condition`, `pN-solution`), чтобы работали заметки на полях.
- Прогресс: `progress.ts` — `markProblem(chapterId, problemId, { solved?, revealed? })` и `getProblems(chapterId)`: через `ensureProgress()` из `$lib/shell.svelte`, read-modify-write поля `problems` у `ChapterProgress` (`update` перезаписывает поле целиком). Без стора (тесты) — no-op.
- Тесты: прогресс (read-modify-write на фейковом сторе), форматирование. Временный маршрут для скриншотов `src/routes/preview-problem/+page.svelte` можно создать и **удалить до коммита**.
