# E1. Playwright-сценарии критичных путей

- Роль: component-dev (Haiku, medium). Зависит от: I1 слит.
- Владеешь: `e2e/**`. `playwright.config.ts` не менять (если нужно, опиши в отчёте).
- Перед запуском: `npx playwright install chromium` (если браузера нет).

## Сценарии (по CLAUDE.md «Тесты»), по файлу на сценарий

1. `home.spec.ts`: главная открывается, 5 карточек топиков, вкладка карты переключается клавишей `2`, нет ошибок консоли.
2. `levels.spec.ts`: `/dl/attention/` — кнопка уровня → поповер; сдвиг «Сложности» на «Интуиция» → появляется «Применить»; до нажатия текст не меняется; после — блок `Variant c="1"` видим, `c="2-4"` скрыт; URL содержит `c=1`; перезагрузка сохраняет уровень.
3. `lab.spec.ts`: «Запустить» на стартовом коде → панель результата со статусом fail (Pyodide с CDN, таймаут теста 180 с); подстановка эталона (возьми `labs/dl-attention-numpy/solution.py` через `fs`) в редактор → все тесты зелёные. Пометь `test.slow()`.
4. `notes.spec.ts`: выделение текста в абзаце → кнопка «Заметка» → ввод текста → сохранение → карточка на полях; после перезагрузки заметка на месте.
5. `progress.spec.ts`: «Отметить пройденным» → перезагрузка → состояние сохранено; на главной появляется «Продолжить».
6. `search-shortcuts.spec.ts`: `?` открывает справку шорткатов, `Esc` закрывает; `T` переключает тему (`data-theme` на html); `Ctrl+K` открывает поиск, запрос «softmax» даёт результат (после сборки с Pagefind).

Селекторы — по ролям/тексту/`data-*`, не по классам. Общие хелперы в `e2e/helpers.ts` (сбор ошибок консоли).

## Критерии приёмки

`npm run test:e2e` зелёный (все 6 файлов). Если сценарий падает из-за бага в приложении, а не в тесте: не чини приложение, пометь тест `test.fixme` с описанием и опиши баг в отчёте (файл, шаги, ожидание/факт).

## Коммит

`test(e2e): critical path scenarios` — без Co-Authored-By и упоминаний агентов/ИИ/моделей.
