# Дорожки работ

Работа разбита на дорожки. Сессия работает только в своей дорожке. Общие файлы трогает только сессия платформы (она же оркестратор). Правила параллельной работы: `CLAUDE.md`, раздел «Несколько сессий».

## Дорожки и пути

| Дорожка | Что делает | Пути, которые принадлежат дорожке |
|---|---|---|
| `platform` | Каркас, конфиги, ядро, движок уровней, заметки, прогресс, поиск, компоненты и стили, маршруты, CI, документация, макет | `package.json`, lock-файл, корневые конфиги, `svelte.config.js`, `vite.config.ts`, `tailwind.config.*`, `src/lib/` (кроме `src/lib/labs/`), `src/routes/`, `.github/`, `docs/`, `tasks/`, `.claude/`, `CLAUDE.md` |
| `dl` | Главы топика DL Theory | `content/dl/**`, `labs/dl-*/` |
| `classic-ml` | Главы топика Classic ML | `content/classic-ml/**`, `labs/classic-ml-*/` |
| `mlops` | Главы топика MLOps Practices | `content/mlops/**`, `labs/mlops-*/` |
| `cs` | Главы топика CompScience | `content/cs/**`, `labs/cs-*/` |
| `compute` | Главы топика Compute | `content/compute/**`, `labs/compute-*/` |
| `labs` | Раннер лабов (Pyodide в Web Worker), инфраструктура тестов эталонов | `src/lib/labs/**`, `labs/_runner/**`, `tests/labs/**` |

Правила:

- Дорожка топика не трогает чужой топик, компоненты и общие файлы. Нужный компонент или стиль просит у платформы пакетом.
- Реестры тем, глав и лабов генерируются сканированием. Ни одна дорожка их не правит руками.
- Если пакету нужен файл вне своей дорожки, пакет разбивается или выстраивается по порядку после слияния владельца.

## Протокол заявок

Заявка на пакет: файл `tasks/claims/<id>.claim`, один файл на один пакет. Конфликтов нет, потому что каждый пакет создаёт свой файл.

Формат файла (четыре строки):

```
сессия: <имя сессии, например s4>
дорожка: <dl | classic-ml | ... >
пакет: <id>
время: <ISO 8601, например 2026-10-16T14:05:00+03:00>
```

Порядок:

1. `git pull` в `main`.
2. Проверить `tasks/claims/`: если есть заявка на тот же пакет или на пакет с пересекающимися владеемыми файлами, не брать. Выбрать другой пакет или ждать.
3. Создать `tasks/claims/<id>.claim`, закоммитить и запушить до начала работы.
4. Если push отклонён (кто-то запушил раньше), `git pull`, повторить проверку шага 2.
5. Работать в своей ветке `task/<id>` и worktree.
6. После слияния пакета удалить `tasks/claims/<id>.claim` отдельным коммитом и запушить.

Снимать чужую заявку может только её владелец или сессия платформы после согласования с пользователем. Заявки старше 24 часов без ветки в `origin` проверяются первой очерёдностью, но сами не снимаются.

## Общие файлы

Общие файлы трогает только сессия платформы (оркестратор): манифесты пакетов, lock-файл, маршруты, корневые конфиги, CI, `docs/*`, `CLAUDE.md`, `tasks/TEMPLATE.md`, `tasks/REPORT-TEMPLATE.md`, `.claude/*`. Остальные сессии просят изменения в пакете или пишут в отчёте.

## Текущий приоритет

1. **Вертикальный срез: DL Theory → Scaled dot-product attention.** Сначала каркас и компоненты (`platform`), затем глава и лаб (`dl`). Порядок: макет согласован, затем срез.
2. **Первая волна контента: DL Theory и Classic ML.** Дорожки `dl` и `classic-ml` идут параллельно. Общие компоненты для них делает `platform` до старта волны.

Вопросы, которые надо решить до волны, в `docs/DECISIONS.md`.
