# Гид по контенту

Как писать главы сайта. Правила взяты из `CLAUDE.md` («Общие соглашения»), `docs/plan.md` (разделы 4–7), `docs/DECISIONS.md` и `docs/design-system.md`. Эталон вида и тона: `docs/mockups/chapter.html`. Если этот гид расходится с `CLAUDE.md`, прав `CLAUDE.md`.

Статус: черновик. Точная схема frontmatter, синтаксис блоков и список компонентов фиксируются в `docs/ARCHITECTURE.md` на шаге контрактов. Примеры ниже ориентировочные; неокончательные места помечены «(уточнится в контрактах)».

## 1. Для кого и тон

- Читатель знает Python и школьную математику, но не обязан помнить прошлые главы. Всё, что нужно раньше, перечисляется в `prereqs`.
- Качество важнее объёма. Одна мысль на абзац, короткие предложения, без канцелярита.
- Без воды: не начинаем с «В этой главе мы рассмотрим», не пересказываем лид в каждом разделе, не пишем «как известно».
- Обращаемся на «вы». Неопределённость говорим честно: «обычно», «зависит от размера модели».
- Структура важнее украшений. Таблица, когда есть два и больше измерения. Список, когда пункты независимы. Код, когда читатель должен его запустить или увидеть форму данных. Формула, когда она точнее слов, и тогда рядом словами, что она говорит.

Плохо: «Внимание является очень важным механизмом, который позволяет моделям учитывать контекст.»
Хорошо: «Внимание даёт каждому токену взвешенную смесь всех остальных токенов. Веса пересчитываются для каждого входа.»

Акценты по темам:

| Тема | Что важно |
|---|---|
| DL Theory | формулы и теория метода; объяснить, почему формула такая |
| Classic ML | сжатые ответы для подготовки к собеседованию; режим вопросов (раздел 7) |
| MLOps Practices | разбор приёма улучшения архитектуры: проблема, решение, цена, когда применять |
| CompScience | алгоритм и оценка сложности; связь с железом там, где она меняет выбор |
| Compute | что делает CUDA/Triton, когда это нужно, а когда нет; без предположений о железе без источника |

## 2. Язык и термины

- Текст на русском. При первом упоминании в главе английский термин в скобках: «внимание (attention)». Дальше только русский. Английский термин остаётся в заголовке, если там принято, и в коде.
- Общепринятые аббревиатуры (GPU, CUDA, HBM, SRAM, API) не переводим. Расшифровываем при первом упоминании, если читатель может их не знать.
- Код, идентификаторы, имена файлов, комментарии в коде: английский. Подписи, текст вокруг кода и рисунков: русский.
- Глоссарий единый: один термин, одна запись. В тексте термин оборачиваем в `<Term id="...">`, инлайн-определений не пишем. Записи и их id лежат в одном файле (путь в `ARCHITECTURE.md`).
- Синонимы не чередуем ради разнообразия: «ключ» везде «ключ», не «индекс» и не «ключевой вектор».
- Стартовые термины:

| Русский | English | id |
|---|---|---|
| внимание | attention | `attention` |
| запрос | query | `query` |
| ключ | key | `key` |
| значение | value | `value` |
| голова внимания | attention head | `attention-head` |
| маска | mask | `mask` |
| логит | logit | `logit` |
| токен | token | `token` |

## 3. Frontmatter главы

Файл `content/<topic>/<slug>/index.svx`. Метаданные только во frontmatter. Отдельного meta-файла нет. Пример для `dl/attention`:

```yaml
---
id: dl/attention                    # <topic>/<slug>, стабилен навсегда
title: Scaled dot-product attention
topic: dl                           # dl | classic-ml | mlops | cs | compute
summary: Как каждый токен решает, на какие другие токены смотреть, и зачем в формуле делитель √d.
prereqs:                            # id глав, которые читатель должен знать
  - dl/softmax
  - dl/dot-product                  # пример, id уточнятся
concepts:                           # понятия, которые глава вводит: id (TermId) и название
  - {id: attention, title: Внимание}
  - {id: query, title: Запрос}
  - {id: key, title: Ключ}
  - {id: value, title: Значение}
keywords:                           # для поиска (Pagefind), сверх заголовка
  - self-attention
  - масштабирование
minutes: 25                         # оценка времени чтения вместе с лабом
labs:
  - dl-attention-numpy              # папка labs/dl-attention-numpy/
sources:                            # раздел 9
  - id: vaswani2017
    kind: paper                     # paper | doc | spec | repo
    title: Attention Is All You Need
    authors: Vaswani A. et al.
    venue: NeurIPS
    year: 2017
    url: https://arxiv.org/abs/1706.03762
    supports: [idea-qkv, math-scale]  # id блоков, которые опираются на источник
  - id: flashattn2022
    kind: paper
    title: "FlashAttention: Fast and Memory-Efficient Exact Attention with IO-Awareness"
    authors: Dao T. et al.
    venue: NeurIPS
    year: 2022
    url: https://arxiv.org/abs/2205.14135
    supports: [hw-flash]
aliases:                            # прежние id главы; заполняется при переименовании
  - dl/scaled-attention
status: draft                       # draft | review | published; необязательно
---
```

Схема (`src/lib/contracts/chapter.ts`) требует у источника `id`, `kind`, `title`, `url`. `id` из латиницы и цифр нужен для `<Cite id>`. `concepts` это объекты `{id, title}`.

Линтер контента проверяет: `prereqs` и `labs` существуют, `concepts` есть в глоссарии, каждый `supports` ссылается на существующий блок, у каждого источника есть `url`. Поле `accessed` (дата проверки) линтер требует для источников с числами (раздел 9).

## 4. Скелет раздела

Порядок разделов фиксирован. Заголовки с якорями:

1. **Идея** `## Идея {#idea}`: 1–2 предложения, что делает метод и зачем. Должно быть понятно на уровне Интуиции.
2. **Интуиция** `## Интуиция {#intuition}`: аналогия, рисунок, демо, пример «на пальцах».
3. **Математика** `## Математика {#math}`: обозначения, формулы, вывод ключевых утверждений.
4. **Код** `## Код {#code}`: лаб или короткий пример с ожидаемым результатом.
5. **Частые ошибки** `## Частые ошибки {#mistakes}`: 3–5 пунктов; самая опасная ошибка во врезке «Осторожно».
6. **Проверь себя** `## Проверь себя {#check}`: 2–4 вопроса `<Quiz>`.
7. **Источники** `## Источники {#sources}`: список генерируется из frontmatter.

Раздел можно опустить, но порядок не меняем. Для Classic ML после «Проверь себя» идёт раздел «Вопросы собеседования» (раздел 7, режим собеседования).

## 5. Уровни

Два слайдера в шапке главы, применяются по кнопке «Применить». Текст не генерируется в рантайме: все варианты собираются при сборке.

### 5.1 Оси и положения

Сложность (`c`), для кого объяснение:

| c | Положение | Что в тексте |
|---|---|---|
| 1 | Интуиция | без предварительной математики: аналогии, простые схемы, одна-две величины, слова вместо символов |
| 2 | Основа | основные определения, одна ключевая формула, маленькие числовые примеры |
| 3 | Формально | полная нотация, предположения, вывод ключевых утверждений |
| 4 | Исследователь | обобщения, варианты, ограничения, открытые вопросы, ссылки на работы |

Глубина (`d`), сколько деталей реализации и железа:

| d | Положение | Что в тексте |
|---|---|---|
| 1 | Идея | что делает и зачем, без кода |
| 2 | Реализация | код, формы тензоров, сложность по времени и памяти, эквиваленты в библиотеках |
| 3 | Железо | иерархия памяти, пропускные способности, ядра, числа с источниками |

Уровень не означает «больше слов про то же». Чем выше уровень, тем больше деталей. Упрощение допустимо, ложь ради простоты нет: на c=1 опускаем детали, но не утверждаем неверного.

### 5.2 Синтаксис

Блок без обёртки виден всем уровням. Минимальный уровень задаётся обёрткой:

```svx
<Level c={3}>

Дисперсия скалярного произведения при независимых компонентах с нулевым средним и единичной дисперсией равна $d$. {#math-var}

</Level>

<Level d={3}>

Матрица $S = QK^\top$ размера $n \times n$ обычно пишется в HBM. {#hw-scores}

</Level>
```

Замена (`Variant`) показывает один из нескольких вариантов одного блока. Диапазоны не пересекаются, и вместе они покрывают все значения оси:

```svx
<Variant c="1">

Аналогия с поиском: запрос это то, что вы ищете, ключи это подписи на карточках каталога, значения это содержимое карточек. Чем лучше подпись совпадает с запросом, тем больше вес у карточки. {#analogy}

</Variant>

<Variant c="2-4">

Для запроса $i$ веса по ключам $j$ нормируются softmax, а выход это взвешенная сумма значений: {#formal-def}

$$
\alpha_{ij} = \mathrm{softmax}_j\!\left(\frac{q_i k_j^\top}{\sqrt{d}}\right), \qquad o_i = \sum_j \alpha_{ij}\, v_j
{#eq-attn}

где $d$ размерность ключей.

</Variant>
```

Вложенность (`<Level c={2}><Level d={2}>`) допустима, но предпочтительна одна ось на блок. Обе обёртки и `Variant` требуют пустой строки между тегом и markdown внутри (иначе mdsvex не разберёт текст).

### 5.3 Правила

- **Ссылки только вниз по уровням.** Нельзя ссылаться на термин, определённый только в более глубоком слое. Если «дисперсия» впервые введена в `<Level c={3}>`, на c=1 и c=2 её нельзя употреблять. Пишем словами: «насколько сильно значения разбросаны». Термин из `prereqs` считается определённым.
- **Символы тоже термины.** Переменную вводим там, где впервые используем, или словами в базовом тексте. В мокапе базовый текст пишет «Q имеет размер n×d», а `d` определён только в `c≥2`. Это нарушение, исправить при написании.
- **Базовый текст верен на всех уровнях.** Он не зависит от слоёв и не противоречит им.
- **Покрытие Variant.** Для одного блока набор `Variant` покрывает все c от 1 до 4 без дыр и наложений. Линтер проверяет.
- **Линтер контента** (`npm run check`) проверяет оба правила по ссылкам `<Term>`, `<Ref>` и символам из формул, если для символа есть запись в глоссарии. Для символов без записи проверка ручная (verifier).

### 5.4 Слой или замена

| Ситуация | Что использовать |
|---|---|
| Дополнительная деталь, которая не меняет смысл базового текста | `<Level c={N}>` |
| Тот же факт подаётся иначе: аналогия вместо формулы | `<Variant>` |
| Вывод или доказательство для подготовленного читателя | `<Level c={3}>` |
| Числа про железо или API | `<Level d={3}>` + источник в `sources` |
| Рисунок, который на разных уровнях показывает разное | `<Variant>` с отдельными `Figure` и своими `id` |
| Предупреждение, верное для всех уровней | базовый `Callout`, без обёртки |
| Подряд больше двух-трёх `Variant` в разделе | пересмотреть раздел, а не множить замены |

## 6. Блоки и id

Блоки нужны заметкам: якорь заметки это `id` блока, цитата и контекст.

- **Формат:** `{#block-id}` в конце абзаца, заголовка, пункта списка. Для display-формулы `{#id}` стоит отдельной строкой сразу после закрывающего `$$` (см. пример в разделе 5.2). Для рисунков проп `id` у `Figure`.
- **Какие блоки:** все содержательные абзацы, формулы, заголовки разделов, пункты списков, на которые можно сослаться заметкой. Переходные фразы, короткие подписи и блоки кода (код адресуется через лаб) id не получают.
- **Именование:** латиница, `kebab-case`, короткие английские слова, префикс по разделу: `idea-qkv`, `math-scale`, `hw-flash`, `mistake-mask`. Имя описывает суть, а не номер («para-3» нельзя).
- **Уникальность:** в пределах главы. Линтер проверяет дубликаты и пустые id.
- **Стабильность:** после публикации id блока не меняется: алиасов у блоков нет. Если блок переписан так, что старый id теряет смысл, заметки к нему станут «осиротевшими», но не потеряются (их можно переякорить вручную).
- **Изменение текста** не меняет id. Если блок переписан полностью, id можно оставить, якорь найдётся по цитате; если блок удалён, id убирается вместе с ним.

## 7. Интерактив

Интерактив добавляем, только когда статика не передаёт суть: зависимость от параметра, динамика, сравнение состояний, пространственная структура, которую трудно описать словами. Статичную формулу, простую таблицу или схему, которую нарисовать SVG, интерактивом не делаем.

Для каждого интерактива обязательны:

- **Подпись** `Figure` с номером «Рис. N» (номер проставляется автоматически по порядку), коротким описанием и текстом «Что заметить» непосредственно под ним.
- **Текстовая альтернатива** в проп `alt`: что показано и ключевые значения, без слов «график» или «картинка».

```svx
<Figure id="fig-attn-arcs" caption="Веса внимания от выбранного токена-запроса" alt="Шесть токенов в ряд; от «кот» к «коврик» дуга самой большой толщины, вес 0.41.">
  <AttentionDemo />
</Figure>

**Что заметить:** веса сумм по строке равны единице, даже если один токен доминирует.
```

**Связь текста и демо.** Сущности цветом связываем через `<Ref>`: `<Ref e="q">запрос</Ref>` окрашивает слово в цвет Q на всех рисунках главы. Ссылка, которая переводит демо в состояние, это `<DemoLink>`. Клик ставит демо в состояние и прокручивает к нему:

```svx
Посмотрите, что будет <DemoLink demo="attention" state={{ scaled: false }}>без масштабирования</DemoLink>: распределение почти вырождается в one-hot.
```

Текст должен читаться без ссылки. Ссылка добавляет, а не заменяет смысл.

**Пошаговые карточки** (`StepCards`) для сложной схемы: 3–6 шагов, в каждом одна фраза о том, что меняется, и состояние рисунка, подсвечивающее нужную матрицу. Шаги не дублируют текст раздела.

**Врезка** `<Callout kind="warn" title="Осторожно">` для типичной ошибки. Одна-две на главу, не больше.

**Отступление** `<Aside title="...">` сворачивается по умолчанию, нужно для читателя, который хочет глубже, но не для основного потока. Не больше двух на раздел.

**Самопроверка** `<Quiz>`: вопрос, ответ по клику. Без баллов, без оценки «знаете / не знаете» и без хранения результатов. Формулировка вопроса конкретная: «что будет с softmax, если…», а не «что вы думаете о…».

```svx
<Quiz id="quiz-scale" q="Что произойдёт с softmax при большом d, если не делить на √d?">

Дисперсия скалярных произведений растёт как $d$, логиты по модулю становятся большими, softmax насыщается в one-hot, и градиенты почти обнуляются.

</Quiz>
```

**Режим собеседования (Classic ML).** Раздел «Вопросы собеседования» `## Вопросы собеседования {#interview}` после «Проверь себя». Вопросы короткие, ответ 3–6 строк, с пометкой уровня. Переключатель режима показывает только этот раздел и краткие ответы. Вопросы пишутся как `<Quiz kind="interview">` (бейдж «Собеседование», без оценок).

## 8. Формулы

Рендер KaTeX при сборке. Inline: `$...$`. Display: `$$` на своих строках; `{#id}` на отдельной строке сразу после закрывающего `$$`.

Нотация по всему сайту:

- **Скаляры:** курсив, `d`, `n`, `\alpha_{ij}`.
- **Матрицы:** заглавные прямые, `Q`, `K`, `V`, `S`. Жирный не используем (так в мокапе).
- **Векторы:** строчные с индексом строки, `q_i`, `k_j`, `v_j`, `o_i`.
- **Транспонирование:** `^\top`, например `k_j^\top` и `QK^\top`.
- **Скалярное произведение:** `q \cdot k` в тексте, `q_i k_j^\top` в матричной записи.
- **Размеры:** `Q \in \mathbb{R}^{n \times d}`.
- **Softmax:** `\mathrm{softmax}`, не `\text{softmax}` и не `softmax()` в формуле.
- **Дисперсия и ожидание:** `\mathrm{Var}`, `\mathbb{E}`.
- **Индексы:** `i` запрос, `j` ключ, `t` компонента вектора.
- **Единицы и байты:** в тексте, не в формуле (`67 млн значений`, `2 байта` на элемент FP16 с источником).

Формула в тексте объясняется словами сразу после. Одна формула на идею; длинные выкладки разбиваются на шаги с `\\` или несколькими display-блоками, каждый с id.

Пользовательских макросов KaTeX в тексте не объявляем. Если нужен новый, он добавляется в конфиг KaTeX в одном месте (путь в `ARCHITECTURE.md`).

## 9. Факты и источники

- **Числа про железо и API** (память, пропускная способность, FLOPS, задержки, лимиты, параметры и поведение API, версии): только с источником в `sources`, который указан в `supports` блока. Число по памяти не пишем: без источника удаляем или формулируем качественно («обычно», «на порядки меньше»).
- **Источники:** `paper` для статьи (arXiv или конференция), `doc` для официальной документации (NVIDIA CUDA, PyTorch, Triton и т.п.), `spec` для стандартов, `repo` для официального кода. Блоги и ответы на форумах допускаются только как ссылка для интуиции, не для чисел.
- **Версия и дата:** для документации указываем версию в `title` или `venue` и поле `accessed: YYYY-MM-DD`. API меняется, без версии число не проверяемо.
- **Оформление в списке** (рендерится из frontmatter): `Vaswani A. et al. Attention Is All You Need. NeurIPS, 2017.` Ссылка в тексте: `<Cite id="vaswani2017" />`.
- **Проверка.** После написания текста отдельный агент `verifier`, который текст не писал, проверяет: каждое число и его источник, формулы (выборочно символьно), соблюдение уровней (раздел 5.3), уникальность и корректность id блоков, существование `prereqs`, `labs`, `concepts`. Он возвращает список замечаний с id блоков. Автор исправляет, verifier перепроверяет только изменённое.

## Ограничения разметки

- В атрибутах компонентов (`q=` у `Quiz`, `caption=`/`notice=`/`alt=` у `Figure` и т.п.) нельзя использовать TeX и фигурные скобки `{}`: Svelte читает их как выражения. Пишите текстом (`z_i − logsumexp(z)`), формулу выносите в тело компонента.

## Серии глав

Продолжение темы — отдельная глава со slug `<база>-<N>` и заголовком «<Название> <N>: <подтема>», например `stats/classical-probability-2` — «Классическая теория вероятности 2: формула Байеса». В `prereqs` — предыдущая часть. Общие компоненты задач (`src/lib/components/problems/`) и математика (`src/lib/prob/`) переиспользуются; новые задачи — новые компоненты `Prob<Глава><N>` в `src/lib/components/demos/`.
