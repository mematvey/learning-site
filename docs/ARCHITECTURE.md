# Архитектура

> Точные схемы (Zod) и API компонентов фиксируются на шаге контрактов; этот документ задаёт их содержание.

Связанные документы: `CLAUDE.md` (соглашения), `docs/plan.md` (задание), `docs/DECISIONS.md` (решения), `docs/design-system.md` (токены и компоненты), `docs/CONTENT-GUIDE.md` (как писать главы).

## 1. Обзор и принципы

Сайт-учебник: набор учебников по темам (`dl`, `classic-ml`, `mlops`, `cs`, `compute`), статический, публикуется на GitHub Pages.

| Принцип | Следствие |
|---|---|
| Статический сайт | Нет серверной части. `adapter-static`, весь HTML получается prerender-ом. |
| Всё при сборке | Уровни, формулы (KaTeX), реестры, граф пререквизитов, индекс поиска строятся в CI. В рантайме нет генерации текста. |
| Масштабирование без правки ядра | Новая тема, глава или лаб это новая папка с файлами по схеме. Код в `src/lib/` и `src/routes/` не меняется. |
| Реестры генерируются | Темы, главы, лабы, глоссарий и граф находятся сканированием папок. Руками не правятся. |
| Контракт важнее реализации | Данные описаны схемами с версией; модули общаются через типизированные интерфейсы. |
| Пользовательские данные отдельно | `user-data/` не попадает ни в репозиторий сайта, ни в сборку. |
| Локальность по умолчанию | Прогресс и заметки работают офлайн (IndexedDB); синхронизация опциональна. |

Границы: на сайте нет аккаунтов, аналитики, самооценок, рекомендателя «что дальше». Лабы выполняются в браузере пользователя без сети.

```
                +--------------------- GitHub Pages (статика) ---------------------+
 content/ ----> |  HTML глав (prerender) + JS-чанки + Pagefind-индекс + бенчмарки  |
 labs/    ----> |                                                                  |
                |   браузер: IndexedDB (прогресс, заметки) <--> Pyodide Worker     |
                +--------------------------------|---------------------------------+
                                                 | опционально, fine-grained токен
                                                 v
                                  приватный репозиторий данных (GitHub API)
                                                 |
                                                 v
                          клон на машине автора --> notes pack --> агент
```

Уточнение ориентира из `docs/plan.md` §3.

```
.github/workflows/           ci.yml (проверки, сборка, деплой)
docs/
  ARCHITECTURE.md  design-system.md  CONTENT-GUIDE.md  LANES.md  DECISIONS.md  plan.md
  mockups/                   статический макет (эталон вида), не переиспользуется как код
tasks/                       TEMPLATE.md, REPORT-TEMPLATE.md, claims/
content/
  <topic>/
    topic.yaml               метаданные темы (id, название, акцент, порядок)
    <slug>/index.svx         глава: frontmatter + mdsvex
    <slug>/figures/          локальные данные и ассеты главы (необязательно)
labs/<lab-id>/               lab.yaml, starter.py, solution.py, tests_visible.py, tests_hidden.py
data/
  benchmarks/*.json          предрасчитанные бенчмарки (Compute, DL)
  aliases.yaml               таблица алиасов id глав
  glossary/*.yaml            термины
src/
  lib/                       модули (раздел 4)
  routes/                    тонкие маршруты; контент подключается автоматически
  generated/                 реестры (в .gitignore, создаются gen-registry)
scripts/                     check-content, gen-registry, notes-pack, lab-check, gen-notebook
tests/                       unit/ (Vitest), e2e/ (Playwright), labs/ (pytest)

```

Что в `.gitignore` (часть уже есть): `node_modules/`, `build/`, `.svelte-kit/`, `__pycache__/`, `.venv/`, `.worktrees/` (worktree параллельных задач), `user-data/`, `src/generated/`, `static/pagefind/`.

`user-data/` по решению 2 это рабочая копия приватного репозитория данных. Допустимы два варианта: клон лежит вне репозитория сайта (путь в `USER_DATA_DIR`), либо внутри как игнорируемая папка. Скрипты читают путь из переменной окружения, по умолчанию `./user-data`. В любом случае папка не коммитится сюда и не попадает в сборку (Vite не импортирует её, `check-content` падает, если находит её в `git ls-files`).

Расположение `src/generated/` вместо коммита реестров: исключает конфликты слияния. Генерация запускается хуками `predev`, `prebuild`, `precheck`.

## 3. Поток сборки

```
content/**/index.svx  labs/*/lab.yaml  data/**  content/*/topic.yaml
          |
          v
 [1] scripts/check-content   (схемы, block id, уровни/термины, ссылки, цикл пререквизитов)
          |  ошибка -> сборка падает
          v
 [2] scripts/gen-registry    ->  src/generated/
          |                       topics.json  chapters.json  labs.json
          |                       glossary.json  prereq-graph.json  aliases.json  search-meta.json
          v
 [3] Vite + mdsvex
          |   remark: {#block-id} -> id атрибут и запись в карту блоков
          |   remark: <Level>/<Variant> -> валидация уровней, метаданные слоя
          |   remark-math + rehype-katex (формулы при сборке)
          |   rehype: Term/глоссарий, нормализация ссылок между главами (через алиасы)
          v
 [4] SvelteKit prerender (adapter-static, entries из реестра глав)
          |   build/  (HTML всех слоёв + JS-чанки по главам)
          v
 [5] pagefind --site build   -> build/pagefind/  (индекс всех слоёв с метками уровня)
          v
 [6] actions/upload-pages-artifact -> deploy-pages
          base path = /<repo>  (kit.paths.base, BASE_PATH из CI; локально пусто)
```

Ключевые решения:

- **Все слои уровней присутствуют в HTML.** Видимость переключает клиентский код (атрибуты на `<html>`/контейнере и CSS), поэтому поиск индексирует всё, а переключение мгновенно и работает без JS-рендеринга нового текста.
- **Base path** задаётся только через `kit.paths.base`; ссылки строятся через единый хелпер `href()`. Хардкод `/` запрещён линтером.
- **Реестры** это единственный источник правды для маршрутов, навигации, поиска, графа и пред/след главы.
- Чанки Pyodide не входят в начальную загрузку: Worker и пакеты грузятся при первом «Запустить».

```
  notes/       якоря, переякоривание, UI на полях
```

Зависимости направлены вниз: `components` используют `levels`, `charts`, `labs`, `notes`, `progress`; `progress` и `notes` используют интерфейс хранилища; `sync` знает только о хранилище и GitHub API. Циклов между модулями нет.

### 4.1 levels (движок уровней)

Две оси (CLAUDE.md): **Сложность** `c` 1–4 (Интуиция, Основа, Формально, Исследователь), **Глубина** `d` 1–3 (Идея, Реализация, Железо). Состояние: `{c, d}`.

Гибрид (решение 1):

| Конструкция | Смысл | Пример |
|---|---|---|
| `<Level c={3}>` | аддитивный слой, виден при `c >= 3` | вывод формулы |
| `<Level d={3}>` | виден при `d >= 3` | детали памяти GPU |
| `<Level c={2} d={2}>` | виден при обоих условиях (И) | реализация для основного уровня |
| `<Variant c="1">…</Variant>` `<Variant c="2-4">…</Variant>` | заменяемые блоки: показывается ровно один подходящий | интуитивная аналогия против строгого определения |
| без обёртки | виден всегда | базовый текст |

Правила:

- Диапазон `c`/`d` в `Variant` это `"n"` или `"a-b"`. Варианты одной группы должны покрывать всю ось без пробелов и пересечений; проверяется при сборке. Группа это соседние `Variant` без текста между ними (или явный `group`).
- По умолчанию `c=2`, `d=1`; сохранённый выбор берётся из прогресса.
- Выбор не применяется на лету: слайдеры меняют «черновое» состояние, видимый текст меняется по кнопке «Применить» (`DepthControls`). Применённое состояние: запись в прогресс, URL `?c=2&d=3`, атрибуты `data-c`, `data-d` на контейнере главы.
- Приоритет источников: URL, затем сохранённый прогресс, затем значения по умолчанию. Некорректные параметры отбрасываются без ошибки.
- Скрытие делается CSS по атрибутам (`[data-c="1"] [data-min-c="3"] {display:none}`), чтобы не ломать SSR и поиск.
- Заметки, закреплённые в скрытом слое, остаются; в панели помечаются «в слое, который сейчас скрыт», клик предлагает переключить уровень.

Проверка «нет ссылок на термины из более глубоких слоёв» (`check-content`):

1. Для каждого `Term`/определения (`**термин**{#def-…}` или запись глоссария с привязкой к главе) вычисляется минимальный слой, где он определён: `(c_min, d_min)`.
2. Для каждого упоминания (`Term`, `Ref`, ссылка на `#def-…`) берётся слой упоминания.
3. Ошибка, если существует состояние `(c, d)`, в котором упоминание видно, а определение нет, и термин не определён глобально в глоссарии на более раннем уровне или в пререквизитной главе.
4. Для `Variant` проверяется каждая ветвь отдельно.

### 4.2 content

| Часть | Что делает |
|---|---|
| Метаданные | frontmatter глав и `topic.yaml` читаются при сборке и валидируются Zod-схемой |
| Реестры | `topics`, `chapters`, `labs`, `glossary`, `prereq-graph`, `aliases` в `src/generated/`; в рантайме читаются как JSON-модули |
| Граф пререквизитов | вершины: главы; рёбра: `prereqs`; для вершин-понятий `concepts` (какие понятия глава вводит) и `requires` (какие использует). Ацикличность проверяется |
| Алиасы id | `data/aliases.yaml`: `старый-id: новый-id`. Резолвер применяется к ссылкам, прогрессу, заметкам, URL (редирект на каноническую страницу) |
| Навигация | порядок глав темы, пред/след, хлебные крошки; порядок берётся из `topic.yaml` (`order: [slug, ...]`), иначе по `prereqs` (топологически) и алфавиту |

Id неизменны. Переименование: добавляется алиас, старая папка не остаётся.

### 4.3 components

Список из `docs/design-system.md` §4; точный API фиксируется на шаге контрактов.

| Компонент | Содержание API (основные входы) |
|---|---|
| `Figure` | `id` (figureId для заметок), номер, подпись, `alt` (текстовая альтернатива обязательна), слот |
| `Callout` | `kind: warn \| note \| tip`, заголовок |
| `Aside` | заголовок, свёрнуто по умолчанию |
| `StepCards` | массив шагов, связь с состоянием рисунка (`onStep`) |
| `Scrolly` | липкий слот графика, шаги текста, состояние по шагу |
| `Term` | `id` термина глоссария; подсказка при наведении/фокусе |
| `Ref`, `DemoLink` | сущность (цвет `--cat-N`), целевое демо и состояние (`demo`, `state`) |
| `Level`, `Variant` | оси и диапазоны (4.1) |
| `CodeLab` | `lab` (id лаба), режимы, слот для визуализаторов |
| `Quiz` | шаблон вопроса с параметрами, генерация вариантов, показ ответа (без оценок) |
| `PrereqGraph` | отображение `prereq-graph` вокруг текущей главы или темы |
| `DepthControls` | два слайдера + «Применить» |

Связь текста и демо реализует то же, что макет: события наведения на сущность ставят `data-hl` на `<body>`, `DemoLink` вызывает `set(state)` демо через шину событий главы (типизированный регистр демо по имени).

Общие требования: доступность (фокус, ARIA, `prefers-reduced-motion`), цвета только из токенов, у каждого интерактива подпись и текстовая альтернатива.

### 4.4 charts

Обёртки D3 над токенами (`--cat-*`, `--ink-*`, `--grid`): `Line`, `Scatter`, `Heatmap`, `Bar`, `Matrix`, `Histogram`.

- Вход: данные и конфигурация осей/серий; выход: SVG. D3 используется для шкал и путей, DOM рисует Svelte.
- Тема через CSS-переменные, переключение темы не требует перерисовки.
- `prefers-reduced-motion` отключает переходы.
- У каждого графика `title`, `desc`, табличная альтернатива (разворачиваемая таблица данных).
- Те же компоненты рисуют результаты лабов (`LabResult.series`, `arrays`).

### 4.5 labs

```
CodeLab (UI)
   |  run(code, lab.yaml)
   v
LabRunner ---- postMessage ----> Web Worker (Pyodide)
   ^                                  | загрузка Pyodide + numpy (кэш браузера)
   | LabResult (JSON)                 | exec(код пользователя + тесты)
   |                                  v
   +--- таймаут -> worker.terminate() -> новый Worker при следующем запуске
```

- **Изоляция.** Pyodide работает в Web Worker. Сети нет: `fetch`, `XMLHttpRequest`, `WebSocket` в Worker запрещены (переопределяются до запуска), `micropip` и импорт сетевых модулей отключены; нужные пакеты (numpy и т.д.) отдаются с сайта статикой.
- **Таймаут.** Значение `timeout` из `lab.yaml` (по умолчанию 10 с). По истечении `terminate()` и статус `timeout`. Зависший Worker не переиспользуется.
- **Выполнение.** Код пользователя и `tests_visible.py` исполняются в изолированном пространстве имён. Скрытые тесты запускаются тем же Worker-ом, но сообщаются только именем и статусом (без ожидаемых значений). Порядок: сначала код, потом видимые, потом скрытые.
- **Результат.** Worker возвращает JSON по формату `LabResult` (5.3). Любая ошибка (синтаксис, исключение, timeout, нехватка памяти) превращается в `LabResult` со статусом `error`/`timeout`, а не в необработанное исключение.
- **JS-рантайм.** `runtime: js` исполняется в отдельном Worker с теми же ограничениями и тем же форматом результата.
- **Визуализаторы.** Реестр `type -> компонент`. Базовые: `curve` (series), `heatmap` (arrays), `table` (metrics), `diff` (тесты). Лаб лишь называет типы и привязывает поля `LabResult`. Новый тип добавляется регистрацией компонента (раздел 11).
- **Черновики.** `CodeLab` пишет код в `ProgressStore` (debounce); см. 4.6.

### 4.6 progress

`ProgressStore` это интерфейс; прикладной код не знает, где данные лежат.

| Метод (смысл) | Назначение |
|---|---|
| `get(chapterId)` / `getLab(labId)` | прочитать запись |
| `update(patch)` | атомарно изменить запись, обновить `updated_at` |
| `list()` | все записи (для экспорта и синхронизации) |
| `export()` / `import(json, mode: merge \| replace)` | перенос между устройствами |
| `subscribe(cb)` | реактивность для UI |

Адаптеры: `IndexedDBAdapter` (по умолчанию), `MemoryAdapter` (тесты), `GitHubSyncAdapter` (зеркалит записи в приватный репозиторий, раздел 4.8). Автосохранение без действий пользователя; только необязательная кнопка «отметить пройденным».

Схема записи в 5.5. Версия схемы хранится в метаданных хранилища. Миграции это упорядоченные чистые функции `v(n) -> v(n+1)`; при открытии хранилище применяет недостающие. Незнакомая более новая версия: режим «только чтение» + предупреждение, данные не затираются.

Черновики лабов: у каждого черновика хэш стартового кода, с которого он создан. Если `lab.yaml`/`starter.py` изменились (хэш не совпал), черновик не удаляется, показывается предупреждение с действиями «оставить мой код», «показать новый старт рядом», «сбросить».

### 4.7 notes

Подробности формата в 5.4. Механизм:

1. Пользователь выделяет текст (или рисунок/формулу) и жмёт «заметка» (`N`).
2. По выделению строится якорь: `blockId` ближайшего блока с `{#id}`, `exact` (выделенная цитата), `prefix`/`suffix` (до 32 символов контекста), для рисунков `figureId` + элемент.
3. Заметка хранится одним файлом; в UI отображается подсветкой и маркером на полях.
4. При открытии главы якоря разрешаются: сначала по `blockId`, затем в нём ищется `exact` с проверкой контекста. Блок пропал или изменился: поиск `exact` по всей главе (нечёткое совпадение с порогом), при успехе якорь обновляется (переякоривание); при неудаче статус позиции `orphaned`, заметка остаётся в списке главы с исходной цитатой.
5. Заметки с id главы-алиаса переносятся на каноническую главу.

Разрешение якоря это чистая функция `(anchor, chapterDOM/text) -> {status, range}` и покрывается Vitest.

### 4.8 sync

Решение 2: IndexedDB локально + коммиты через GitHub API в отдельный приватный репозиторий данных.

- **Токен.** Fine-grained personal access token только на один приватный репозиторий данных, права `Contents: read/write`, больше ничего. Токен вводится пользователем в настройках и хранится в `IndexedDB` отдельным хранилищем, не экспортируется ни в JSON, ни в URL, не логируется; кнопка «забыть токен». Токен используется только запросами к `api.github.com`. Предупреждение в UI: токен лежит в браузере, ограничивайте права и срок действия.
- **Модель.** Один файл на запись (заметка, ответ, запись прогресса, черновик): нет конфликтов слияния между разными записями. Раскладка в репозитории данных повторяет `user-data/` (5.4–5.5).
- **Алгоритм.** Локальные изменения копятся в очереди; по таймеру или кнопке: получить дерево (`git/trees`, ETag), сравнить с локальным состоянием по `updated_at` и sha, затем PUT (`contents`) изменённых файлов и DELETE удалённых. Сначала pull, потом push.
- **Конфликты** возможны только для одной и той же записи на двух устройствах: побеждает запись с большим `updated_at` (для прогресса слияние по полям: `visited` объединение, `labs_passed` объединение, `scroll` последний); проигравшая версия сохраняется в `.conflicts/<id>.<time>.json` и показывается пользователю.
- **Отказоустойчивость.** Офлайн или лимит API: очередь остаётся, UI показывает статус, данные не теряются. Нет токена: синхронизация выключена, всё работает локально.
- **Агент** читает заметки из клона репозитория данных; сайт и агент не соединены напрямую.

### 4.9 search

Pagefind индексирует `build/` после prerender.

- Индексируются **все слои** (все `Level`/`Variant` присутствуют в HTML). Каждый блок слоя несёт `data-pagefind-meta`/фильтры с минимальным уровнем (`c`, `d`), чтобы результаты показывали метку уровня («Формально», «Железо»).
- Фильтры: тема, тип (глава, лаб, глоссарий), уровень. Заголовок, `summary`, `keywords` из frontmatter повышают вес.
- Клиент: ленивая загрузка `pagefind.js`, UI собственный на токенах; `mod+K` и `/` фокусируют поле.
- Результат ведёт на главу с `#block-id` и, если слой скрыт, предлагает переключить уровень.
- Базовый путь учитывается (`/<repo>/pagefind/`).

### 4.10 shortcuts

Поведение и таблица клавиш определены в `docs/mockups/CONTRACT.md` («Шорткаты»). Модуль действует через атрибуты (`data-search`, `data-theme-toggle`, `data-levels-toggle`, `data-prev`, `data-next`, `data-note-btn`, `data-mark-done`, `data-home`) и не знает о внутренностях компонентов. `<kbd data-kbd="mod+k">` перерисовывается в нотацию платформы. Однобуквенные клавиши отключены в `input`, `textarea`, `[contenteditable]`. Редактор лаба обрабатывает свои сочетания сам (`mod+Enter`, `mod+S`, `mod+Shift+Backspace`).

### 4.11 theme

- Светлая и тёмная темы, переключатель (`T`), выбор хранится локально; без выбора следует `prefers-color-scheme`. Атрибут `data-theme` на `<html>` ставится inline-скриптом до первой отрисовки (без мигания).
- Акцент темы: `data-topic="<id>"` на `<html>` даёт `--topic` и `--topic-soft` (тонкая смена между темами).
- Все стили через токены `src/lib/theme/tokens.css` (источник: `docs/design-system.md`), сырых цветов в компонентах нет.
- `prefers-reduced-motion` отключает анимации глобально.

Таблицы описывают содержание; поля `?` необязательны.

### 5.1 Frontmatter главы (`content/<topic>/<slug>/index.svx`)

Схема: `src/lib/contracts/chapter.ts` (`ChapterFrontmatter`). Поля с пометкой «нет» необязательны.

| Поле | Тип | Обяз. | Смысл |
|---|---|---|---|
| `id` | `<topic>/<slug>` (ChapterId) | да | стабильный id; совпадает с путём |
| `title` | string | да | название главы |
| `topic` | id темы | да | `dl`, `classic-ml`, `mlops`, `cs`, `compute` |
| `summary` | string | да | 1–2 предложения; для карточек и поиска |
| `prereqs` | ChapterId[] | да (может быть `[]`) | граф зависимостей между главами |
| `concepts` | `{id, title}[]` | нет | понятия, которые вводит глава (узлы графа понятий); `id` это TermId |
| `requires` | TermId[] | нет | понятия, которые глава использует |
| `keywords` | string[] | да | ключевые слова для поиска |
| `minutes` | число или `{c1..c4}` | да | оценка времени чтения; в объекте хотя бы одно из `c1..c4` |
| `labs` | LabId[] | нет | лабы главы; должны существовать |
| `sources` | `Source[]` | нет в схеме; линтер требует для глав с фактами | источники фактов и чисел про железо/API |
| `aliases` | ChapterId[] | нет | прежние id главы (сводятся в `data/aliases.yaml` при генерации) |
| `status` | `draft \| review \| published` | нет | draft-главы не попадают в навигацию продакшена |

`Source`: `id` (латиница и цифры, для `<Cite id>`), `kind` (`paper \| doc \| spec \| repo`), `title` и `url` обязательны. Необязательны `authors`, `venue`, `year`, `note`, `supports` (id блоков, которые опираются на источник). `accessed` (ISO-дата проверки) в схеме необязателен; линтер требует его для документации с числами про железо и API.

```yaml
---
id: dl/attention
title: Scaled dot-product attention
topic: dl
summary: Как запрос, ключ и значение превращаются во взвешенную сумму и зачем делить на корень из d.
prereqs: [dl/softmax, dl/matmul-basics]
concepts: [{id: attention-scores, title: Оценки внимания}]
keywords: [attention, softmax, scaled dot-product]
minutes: {c1: 8, c2: 15, c3: 25, c4: 35}
labs: [dl-attention-numpy]
sources:
  - {id: vaswani2017, kind: paper, title: "Attention Is All You Need", url: "https://arxiv.org/abs/1706.03762", year: 2017, supports: [idea-qkv]}
aliases: []
status: draft
---
```

Блоки в теле:

```svx
Оценки внимания считаются как скалярное произведение запроса и ключа. {#scores-def}

<Level c={3}>

$$
\mathrm{softmax}\!\left(\frac{QK^\top}{\sqrt{d_k}}\right)V
$$
{#attn-formula}

</Level>

<Figure id="fig-attn-heatmap" alt="Тепловая карта весов внимания">...</Figure>
```

`{#id}` в конце абзаца, заголовка или пункта списка. Для display-формулы `{#id}` стоит отдельной строкой сразу после закрывающего `$$`. У рисунка id задаётся пропом `id`.

### 5.2 `labs/<lab-id>/lab.yaml`

Схема: `src/lib/contracts/lab.ts` (`Lab`). Пути относительны папки лаба.

| Поле | Тип | Обяз. | Смысл |
|---|---|---|---|
| `id` | `<topic>-<slug>` (LabId) | да | совпадает с именем папки |
| `title` | string | да | название |
| `chapter` | `<topic>/<slug>` (ChapterId) | да | id главы-владельца |
| `runtime` | `pyodide \| js \| simulator \| external-notebook` | да | среда выполнения |
| `starter` | path | да, кроме `simulator` | стартовый код (`starter.py`) |
| `solution` | path | да, кроме `simulator` | эталон (`solution.py`), не попадает в сборку сайта |
| `tests.visible` | path | да, кроме `simulator` | `tests_visible.py`, показываются и дают диффы |
| `tests.hidden` | path | нет | `tests_hidden.py`, в клиент отдаётся как данные для выполнения, текст не показывается |

| `timeout` | секунды | нет | по умолчанию 10, не больше 120 |
| `packages` | string[] | нет | пакеты Pyodide (из белого списка линтера) |
| `external` | `{colab?, kaggle?, gpu?}` | да для `external-notebook` | для Compute/DL: генерировать ноутбук (раздел 6) |

```yaml
id: dl-attention-numpy
title: Attention на NumPy
chapter: dl/attention
runtime: pyodide
starter: starter.py
solution: solution.py
tests: {visible: tests_visible.py, hidden: tests_hidden.py}
visualizers:
  - {type: heatmap, source: arrays.weights}
  - {type: curve, source: series.loss}

packages: [numpy]
```

Скрытые тесты это не секрет от пользователя с devtools; цель не защита, а исключение подгонки под видимые проверки. `solution.py` в клиентский бандл не включается.

### 5.3 `LabResult`

Схема: `src/lib/contracts/lab-result.ts`. Ключи snake_case: формат пишут Worker, Python и внешние запуски.

| Поле | Тип | Обяз. | Смысл |
|---|---|---|---|
| `schema_version` | `1` | да | версия формата; другая версия отвергается с понятной ошибкой |
| `lab_id` | LabId | да | id лаба |

### 5.6 Версии схем

| Объект | Поле версии | Правило |
|---|---|---|
| frontmatter, `lab.yaml`, `topic.yaml` | константа `CONTENT_SCHEMA_VERSION` в `src/lib/contracts` | меняет автор ядра, контент мигрируется скриптом |
| `LabResult` | `schema_version` в результате | клиент отвергает несовместимый импорт с понятной ошибкой |
| заметки, прогресс, настройки | `schemaVersion` в каждой записи | миграции `vN -> vN+1` при чтении; запись в новом формате |
| хранилище IndexedDB | версия БД | `onupgradeneeded` вызывает миграции |

Изменение формата это новая версия + миграция + тест миграции на фикстуре.

## 6. Лабы для Compute и DL (решение 4)

Kernel-код (CUDA, Triton) на Pages не запускается; DL-лабы в Pyodide работают на NumPy (torch в Pyodide недоступен). Три механизма, вместе:

| Механизм | Что это | Где живёт |
|---|---|---|
| Браузерные симуляторы | иерархия памяти, варпы, коалесцирование, occupancy, тайлинг; чистый JS/TS с интерактивом, параметры меняет пользователь | `src/lib/labs/simulators/` или компонент главы; описание в `lab.yaml` типом `simulator` |
| Предрасчитанные бенчмарки | реальные замеры на конкретном железе, показываются графиками | `data/benchmarks/*.json` |
| Внешний запуск | «Открыть в Colab/Kaggle»: сгенерированный ноутбук; результат импортируется обратно | `scripts/gen-notebook`, UI «Импорт результата» |

Бенчмарки (`data/benchmarks/<id>.json`):

| Поле | Смысл |
|---|---|
| `id`, `title`, `schema_version` | служебные |
| `hardware` | `{gpu, cpu?, driver?, cuda?, memory?}` обязательны, источник железа |
| `software` | версии (torch, triton, компилятор) |
| `method` | как измерено (прогревы, число повторов, статистика) |
| `date` | дата замера |
| `series`/`table` | данные в формате, понятном `charts` |
| `source` | `{url?, command, repo_commit}` откуда взято и как воспроизвести |

`check-content` требует `hardware` и `date` у каждого бенчмарка, а числа в тексте главы ссылаются на запись бенчмарка или на `sources`.

Ноутбук (`gen-notebook <lab-id>`): `.ipynb` собирается из `lab.yaml`: ячейка установки, стартовый код (или решение, если выбран режим «проверить эталон»), видимые тесты, ячейка, выводящая JSON в формате `LabResult` (`source: external`, `env` с железом). Ссылка Colab ведёт на файл в репозитории данных или Gist; Kaggle получает скачиваемый `.ipynb`. Пользователь запускает, копирует JSON и загружает на сайте через «Импорт результата»; он валидируется той же схемой и рисуется теми же визуализаторами. Импорт сохраняется в прогрессе как `last_result` с пометкой `external`; пройденный внешний запуск засчитывается как `passed`.

## 7. Заметки и агент

```
сайт -> заметки (IndexedDB) -> sync -> приватный репозиторий данных -> клон (user-data/)
                                                                         |
                                           npm run notes:pack -- --status open
                                                                         v
                                                     пакет markdown -> агент
                                                                         v
                                   <ulid>.answer.md (в клон)  +  правки главы отдельной веткой на ревью
                                                                         |
                                   commit/push данных -> sync -> на сайте статус answered
```

Команда: `notes pack --status open [--topic X] [--chapter dl/attention] [--out file]`.

- Читает `user-data/notes/**`, для каждой заметки со статусом `open` находит блок в главе по `blockId` и вырезает контекст (абзац, соседние блоки, заголовок раздела, формулы).
- Группирует по главам и сортирует по порядку в тексте.
- Orphaned-заметки идут в отдельный раздел с исходной цитатой.
- Выводит один markdown-файл (по умолчанию в `user-data/packs/<date>.md`; `packs/` не коммитится в сайт).

Пример пакета:

```markdown
# Пакет заметок: 2026-10-16 (open: 2)

## dl/attention  (content/dl/attention/index.svx)

### 01JC3X4N8Q0Z9M7K2V5R6T1WYA  [block: scores-def, anchored]
Цитата: «скалярное произведение запроса и ключа»
Контекст раздела «Интуиция»:
> Оценки внимания считаются как скалярное произведение запроса и ключа. Дальше они
> нормируются softmax-ом ...
Комментарий автора: Почему именно скалярное, а не расстояние?
```

Правила:

- Агент никогда не правит главу молча. Любая правка текста главы это отдельная ветка/изменение, которое автор смотрит и принимает; в ответе есть ссылка.
- Ответ записывается файлом рядом с заметкой; после коммита в репозиторий данных заметка получает `status: answered` (скрипт `notes pack --mark-answered` или правка при чтении `.answer.md`, правило: наличие ответа = answered).
- Ответ может ссылаться на источники; факты проверяются так же, как контент.

## 8. Скрипты (`scripts/`)

| Скрипт | Что делает | Команда (будет) |
|---|---|---|
| `check-content` | frontmatter по схеме; соответствие `id` пути; уникальность и формат block id (`kebab-case`, уникален в главе); `Figure id`; корректность `Level`/`Variant`; уровни и термины (4.1); битые ссылки между главами и якоря; ссылки на лабы; пререквизиты существуют, граф без циклов; наличие `sources` и `alt`; `user-data/` не в git | `npm run check:content` |
| `gen-registry` | сканирует `content/`, `labs/`, `data/`, пишет `src/generated/*`, применяет алиасы | `npm run gen` (авто в `predev`/`prebuild`) |
| `notes-pack` | пакет открытых заметок (раздел 7) | `npm run notes:pack -- --status open` |
| `lab-check` | для каждого лаба: эталон проходит все тесты, стартовый код не проходит; запуск в тех же ограничениях, что и в браузере (numpy, таймаут) | `uv run python scripts/lab_check.py` / `uv run pytest tests/labs` |
| `gen-notebook` | `.ipynb` из `lab.yaml` | `uv run python scripts/gen_notebook.py <lab-id>` |

Сводные команды (появятся в вертикальном срезе):

| Команда | Состав |
|---|---|
| `npm run dev` | gen + Vite dev |
| `npm run build` | gen + check:content + build + pagefind |
| `npm run check` | svelte-check, ESLint, Prettier --check, Vitest, check:content |
| `npm run test:e2e` | Playwright |
| `uv run ruff check` / `uv run ruff format --check` | Python-инструменты и лабы |
| `uv run pytest` | тесты эталонов лабов |

Python-скрипты и код лабов на английском (идентификаторы, комментарии); `check-content` написан на TypeScript (общая схема Zod с сайтом), `lab-check` и `gen-notebook` на Python.

## 9. CI (GitHub Actions)

```
push / PR
  |
  +-- job checks ---- npm ci (кэш npm) -> gen -> npm run check
  |                   uv sync (кэш uv)  -> ruff check -> pytest (лабы: эталон проходит, старт нет)
  |
  +-- job build ----- (needs: checks) npm run build с BASE_PATH=/<repo>
  |                   артефакт: build/ (включая pagefind)
  |
  +-- job e2e ------- (needs: build, опционально на PR) Playwright на build/
  |
  +-- job deploy ---- (needs: build, только main) upload-pages-artifact -> deploy-pages
```

- Кэш: `actions/setup-node` с `cache: npm`, кэш `uv`, кэш браузеров Playwright; кэш Pyodide-файлов не нужен (отдаются статикой из сборки).
- Деплой только с `main`; PR получают проверки и сборку без деплоя.
- Права: `pages: write`, `id-token: write` только в job `deploy`; остальные `contents: read`.
- Конкурентность: `concurrency: pages` с отменой устаревших запусков.
- Секретов для сайта нет (сборка не использует токены). Токен синхронизации живёт только в браузере пользователя.
- **Видимость.** Основной репозиторий пока приватный. GitHub Pages из приватного репозитория требует платного плана; иначе на момент деплоя репозиторий делается публичным. Пока Pages недоступен, CI собирает и выкладывает сборку как артефакт job, а деплой-job можно отключить условием. Контент репозитория сайта не содержит личных данных, поэтому публикация безопасна.

## 10. Тестирование

По CLAUDE.md: тесты на ключевую логику, coverage не цель.

| Уровень | Инструмент | Что покрывается |
|---|---|---|
| Unit | Vitest | движок уровней (видимость, `Variant`-группы, парсинг URL `?c=&d=`); разрешение и переякоривание якорей заметок; `ProgressStore` (адаптеры, миграции, экспорт/импорт, предупреждение о смене стартера); разбор и слияние при синхронизации (на моках GitHub API); раннер лабов (таймаут, формирование `LabResult`, на мок-Worker-е); поиск (разбор метаданных уровня); резолвер алиасов; проверки `check-content` на фикстурах (ошибка находится) |
| E2E | Playwright (несколько сценариев) | страница главы открывается; «Применить» меняет текст; лаб запускается и показывает результат; заметка создаётся; прогресс сохраняется и восстанавливается после перезагрузки |
| Python | pytest + ruff | эталон каждого лаба проходит, стартовый код не проходит (CI); `gen_notebook` даёт валидный ноутбук |
| Визуальное | Playwright скриншоты обеих тем | оценивается отдельно, не как автотест |

Не тестируем: оформление компонентов, тривиальные геттеры, отдельные графики на уровне пикселей.

## 11. Расширяемость

Без правки ядра (`src/lib/`, `src/routes/`, конфиги):

| Что добавить | Шаги |
|---|---|
| Тема | создать `content/<id>/topic.yaml` (название, описание, порядок, акцент) и главы; id темы берётся из реестра, а не из перечисления в коде; акцент задаётся в `topic.yaml`, токены не правятся |
| Глава | папка `content/<topic>/<slug>/index.svx` с frontmatter; реестр, маршрут, навигация, поиск, граф подхватятся при сборке |
| Лаб | папка `labs/<topic>-<slug>/` с файлами по схеме; id лаба в `labs:` главы; `<CodeLab lab="..."/>` в тексте |
| Термин глоссария | запись в `data/glossary/*.yaml`; доступен как `<Term id>` |
| Тип визуализатора | компонент в `src/lib/labs/visualizers/` + регистрация в реестре визуализаторов (одна строка); лабы ссылаются на тип в `lab.yaml` |
| Тип графика | компонент в `src/lib/charts/` на токенах; экспорт из индекса |
| Бенчмарк | `data/benchmarks/<id>.json` с `hardware` и `date` |
| Переименование главы | новая папка, строка в `data/aliases.yaml` |

## 12. Что пересмотреть при росте

| Область | Признак | Что делать |
|---|---|---|
| Поиск | индекс Pagefind > нескольких десятков МБ, заметная задержка первого поиска | индексировать слои выборочно, дробить по темам, фильтры по умолчанию |
| Размер Pyodide | первый запуск лаба долгий | предзагрузка по hover, сервис-воркер/кэш, минимальный набор пакетов, выбор более лёгкой среды для простых лабов |
| Время сборки | prerender + KaTeX на сотнях глав | инкрементальный кэш KaTeX, кэш сборки Vite в Actions, разбивка на несколько job |
| Размер HTML глав | все слои в HTML раздувают страницу | ленивая подгрузка тяжёлых слоёв при сохранении индекса поиска (отдельные индексируемые фрагменты) |
| Граф пререквизитов | сотни вершин | кластеризация по темам, ленивый рендеринг |
| Синхронизация | много файлов, лимиты GitHub API | пакетные коммиты через Git Data API, сжатие в снимки |
| Репозиторий данных | рост истории | архивирование старых заметок, shallow clone |
| Pages из приватного репозитория | нет платного плана | сделать репозиторий публичным или хостить статику иначе |
| Контент | противоречия между уровнями | усилить `check-content`, обязательная проверка отдельным проверяющим |
| Хранилище IndexedDB | квоты браузера | напоминание об экспорте, сжатие черновиков |
