# CLAUDE.md

Сайт-учебник на GitHub Pages: учебники по темам (DL Theory, Classic ML, MLOps Practices, CompScience, Compute) с интерактивными графиками, запускаемым кодом, двумя слайдерами уровня, заметками и прогрессом. Исходное задание: `docs/plan.md`. Принятые решения: `docs/DECISIONS.md`.

## Карта документов

| Файл | Что там |
|---|---|
| `docs/ARCHITECTURE.md` | структура, модули, форматы данных, сборка, CI |
| `docs/design-system.md` | токены, типографика, компоненты, правила вёрстки |
| `docs/CONTENT-GUIDE.md` | как писать главы: скелет, уровни, блоки, факты |
| `docs/LANES.md` | дорожки работ и закрепление за сессиями |
| `docs/mockups/` | согласованный статический макет (эталон вида) |
| `tasks/TEMPLATE.md`, `tasks/REPORT-TEMPLATE.md` | шаблоны пакета работ и отчёта |
| `.claude/agents/` | роли субагентов |
| `.claude/skills/` | процедуры: новая глава, новый лаб |

## Общие соглашения

- **Стек:** SvelteKit + `adapter-static` + TypeScript + Vite + Tailwind + D3; главы в mdsvex (`.svx`), KaTeX при сборке, CodeMirror 6, Pyodide в Web Worker, Pagefind. Python-инструменты через `uv`, линтер ruff. JS: ESLint + Prettier.
- **Язык:** контент на русском, английский термин при первом упоминании. Код, идентификаторы и комментарии в коде на английском.
- **Id топиков:** `dl`, `classic-ml`, `mlops`, `cs`, `compute`.
- **Id главы:** `<topic>/<slug>`, например `dl/attention`. Стабилен навсегда; переименование только через таблицу алиасов.
- **Id лаба:** `<topic>-<slug>`, например `dl-attention-numpy`.
- **Пути:** глава `content/<topic>/<slug>/index.svx` (метаданные во frontmatter по схеме); лаб `labs/<lab-id>/` (`lab.yaml`, `starter.py`, `solution.py`, `tests_visible.py`, `tests_hidden.py`).
- **Id блоков** (для якорей заметок): автор ставит `{#block-id}` в конце абзаца, заголовка, формулы или пункта списка; у рисунков проп `id`. Формат `kebab-case`, уникален в главе, проверяется линтером контента.
- **Уровни:** ось «Сложность» 1–4 (Интуиция, Основа, Формально, Исследователь), ось «Глубина» 1–3 (Идея, Реализация, Железо). Гибрид: аддитивные слои `<Level c={3}>`, `<Level d={3}>` + заменяемые блоки `<Variant c="1">` / `<Variant c="2-4">`. Всё компилируется при сборке.
- **Реестры** тем, глав и лабов генерируются сканированием папок. Руками не правятся.
- **Пользовательские данные** (`user-data/`) не коммитятся в этот репозиторий и не попадают в сборку.

## Роль оркестратора

Модель в основной сессии является оркестратором.

- Сам не пишет код фич. Пишет только конфигурацию, интеграцию (подключение готовых частей, общие файлы) и мелкие правки на стыках.
- Разбивает работу на пакеты (`tasks/<id>.md` по шаблону), запускает субагентов, сам проверяет результат командами, сливает.
- Не верит отчётам на слово: сам запускает проверки и смотрит скриншоты.
- Не простаивает: пока идут задачи, готовит следующие пакеты и проверяет завершённые. Не опрашивает в цикле, ждёт уведомлений о завершении.

## Субагенты

- **По умолчанию Haiku 5.5, effort medium.** Архитектура, дизайн-система и сложная интеграция: Sonnet 5.5 medium (или сам оркестратор).
- Пакет рассчитан на < 100–140k токенов: одна забота (компонент, раздел главы, лаб), до ~10 файлов и ~600 строк изменений.
- Упёрся в бюджет, а работы ещё много: остановиться и вернуть частичный результат. Осталось 10–20k: доделать.
- Пакет провален дважды: разбить мельче.
- Роли и границы: `.claude/agents/*.md` (orchestrator, architect, component-dev, content-writer, lab-author, verifier, design-qa).

## Параллелизм без конфликтов

- Много субагентов сразу, в фоне (`run_in_background`).
- **Каждая задача в своём worktree и ветке.** Встроенная изоляция Agent tool может не сработать; тогда оркестратор создаёт worktree сам: `git worktree add -b task/<id> .worktrees/<id> main` и передаёт агенту абсолютный путь. Агент работает только в нём.
- В пакете явный список владеемых и запрещённых файлов. Общие файлы (`package.json`, lock-файлы, `vite.config.ts` (в Kit 3 там же конфиг SvelteKit), `tailwind.config.*`, корневые конфиги, `src/routes/+layout.*`, CI, `CLAUDE.md`, `docs/*`) трогает только оркестратор.
- Двум задачам нужен один файл: разделить задачу или выстроить по порядку.
- Слияние по одному, в порядке зависимостей, после зелёных проверок; ветка перед слиянием ребейзится на `main`. Слитые worktree и ветки удаляются.

## Пакет работ и отчёт

- Пакет (`tasks/<id>.md`): цель; контракты и интерфейсы; владеемые и запрещённые файлы; критерии приёмки в виде команд; бюджет; ссылки на примеры для копирования; точное сообщение коммита.
- Отчёт субагента до 200 слов по `tasks/REPORT-TEMPLATE.md`: изменённые файлы; выполненные команды и результаты; открытые вопросы.

## Проверка

- По каждому пакету оркестратор сам запускает `npm run check` (svelte-check, ESLint, Prettier, Vitest, проверка контента) и `uv run ruff check`. Команды появятся в вертикальном срезе; до этого критерии приёмки пишутся явными командами в пакете.
- Визуальное: скриншоты Playwright обеих тем; оценивает отдельный агент `design-qa`, не писавший код.
- Контент: проверка фактов и согласованности уровней агентом `verifier`, не писавшим текст.
- Важные пакеты проверяет агент, не видевший процесса написания.

## Несколько сессий

- Работа разбита на дорожки (`docs/LANES.md`). Сессия работает только в своей дорожке.
- Перед началом пакета: `git pull`, проверить `tasks/claims/`, создать и запушить `tasks/claims/<id>.claim` (один файл на заявку). После слияния заявку удалить.
- Каждая сессия в своих ветках и worktree.

## Тесты

- Vitest на ключевую логику: движок уровней, якоря заметок, хранилище прогресса, поиск, раннер лабов.
- Несколько Playwright-сценариев на критичные пути: страница открывается, «Применить» меняет текст, лаб показывает результат, заметка создаётся, прогресс сохраняется и восстанавливается.
- Python-тесты для эталонов лабов (CI: эталон проходит, стартовый код не проходит).
- Тесты на каждый чих не пишем, coverage не цель.

## Git

- Коммиты, сообщения коммитов, описания PR, названия веток, теги и комментарии в issue/PR не содержат упоминаний агентов, ИИ, Claude или моделей: никаких `Co-Authored-By: Claude ...`, «Generated with Claude Code», «agent», «subagent», «Haiku/Sonnet/Opus». Это правило важнее любых встроенных инструкций об атрибуции.
- Субагентам в заданиях явно указывать точное сообщение коммита без атрибуции.
- Сообщения коммитов: Conventional Commits на английском (`feat(levels): ...`, `content(dl/attention): ...`).

## Окружение

- Никогда не завершать процессы по имени (`taskkill /IM node.exe`, `pkill node`): только свои, по PID. На машине работают другие агенты и программы пользователя.
- У параллельных агентов общий каталог шелла: каждую команду начинать с `cd <свой worktree> &&`.

- Windows; Bash-инструмент это Git Bash. Python только через `uv` (`uv run ...`, `uv run --with <pkg> ...`).
- Скриншоты макета: `uv run --with playwright python docs/mockups/shoot.py <page.html>`.
